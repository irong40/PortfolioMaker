# Audit Context
**Date**: 2026-07-30
**Branch**: feat/sortie-gui
**Author**: Claude Code (Anthropic)
**Base**: origin/main (`c401a83`)

## What Was Built

A pure-visual restyle of the Sortie desktop GUI (`sortie.py`, tkinter). The app
was a single 760x780 scrolling column of 13 stacked `LabelFrame`s; it is now a
six-step rail (Mission / Source / Config / Pre-Flight / Process / Deliver) with
a live connection strip in the header.

The brief was explicit: **"don't change the functionality, just change how it
looks."** So the builder methods were not rewritten. They still pack into
`self._content`; `__init__` re-points `self._content` at the step page that owns
each group before calling each builder. The intended diff is therefore about
*parenting and visibility*, not logic. **Any behavioral difference an auditor
finds is a bug, not a feature.**

## Key Decisions

1. **`self._content` is mutated between builder calls** rather than passing a
   parent argument to each `_build_*` method. Chosen to keep the diff small and
   leave ~600 lines of builder bodies byte-identical. Trade-off documented under
   Areas of Concern — this is the single most fragile thing in the change.

2. **Dropped `in_=self._content` from all five re-pack sites.** Those calls use
   `pack(before=<sibling>)` to reveal hidden panels. `before=` requires both
   widgets to share a packing master. Since each widget's natural parent is now
   its step page, omitting `in_` resolves correctly. Panels linked by `before=`
   were deliberately kept on the same page (PPK+scan on Pre-Flight;
   results+video+advanced+actions+progress on Process).

3. **`_deliver_btn` moved out of `_action_frame`** onto its own Deliver step.
   This is the only widget that changed parent in a way that alters an existing
   code path — and it caused the one real regression found so far (see below).

4. **n8n is rendered as a muted informational chip, not a status dot, and is
   never probed.** ADR 2026-07-27 retired the n8n processing tier (it had
   processed zero jobs ever) and made sortie the system of record. A green dot
   would assert a connection that does not exist. CRM / NodeODM / splat engine
   ARE live probes and get real dots.

5. **Rail entries are freely clickable — no gating.** A wizard that locks steps
   would make previously-reachable controls unreachable, which would itself be a
   functional change.

## Areas of Concern

Ranked by how much they worry me. Please attack these first.

1. **The `self._content` mutation is a latent trap.** Any `_build_*` method
   added later, or any existing one reordered in `__init__`, silently lands its
   widgets on whatever page `self._content` happens to point at — most likely
   `deliver`, the last assignment. Nothing asserts this. Consider whether it
   warrants an explicit parent parameter despite the larger diff.

2. **Cross-page `before=` is now a latent `TclError`.** All five current sites
   were verified same-page, but the invariant is implicit and unenforced. If
   someone later reveals a Process-page widget `before=` something on Deliver,
   it raises at runtime — inside a reveal path that may only execute after a
   long job has finished.

3. **I introduced and then fixed a stale-Drive-upload regression** (commit
   `8b3857f`). Moving `_deliver_btn` out of `_action_frame` meant
   `_on_reset`'s `_action_frame.pack_forget()` no longer hid it, leaving a live
   Drive upload pointed at the previous job's folder after a reset.
   **The real ask for the auditor: this is a whole CLASS of bug — every place
   that hides or shows a container may have been implicitly hiding a child that
   has now moved.** I checked `_action_frame`, `_results_frame`, `_video_panel`,
   `_ppk_frame` and `_adv_frame` by hand. A systematic sweep of every
   `pack_forget()` / `pack()` and every `winfo_children()`-style traversal would
   be far better evidence than my manual pass.

4. **`_last_sort_output` is not cleared by `_on_reset`.** Pre-existing; left
   unchanged deliberately to preserve parity. Second opinion wanted on whether
   parity was the right call here, given the button that guarded it moved.

5. **Window geometry is persisted** (`window_geometry` in `sortie_settings.json`).
   A user with a saved 780x800 geometry from the old layout gets it restored,
   which is narrower than the new 940 minimum. Tk should clamp to minsize, but
   the upgrade path was not tested with a pre-existing settings file.

6. **Mousewheel uses `bind_all`**, inherited from the original. It was already
   global; there are now more nested frames and a rail. Untested whether scroll
   behaves correctly with the pointer over the rail or the nav bar.

7. **Steps hide via `pack_forget()`, not `grid_remove()`.** Hidden pages keep
   their widgets alive, so every `StringVar`/`trace_add` still fires while
   off-screen. That matches the old always-packed behavior, but confirm no
   handler now runs against an unmapped widget in a way that raises.

## Testing Status

- **582 pytest pass** — but this is weak evidence for this change. Only
  `test_panorama.py` imports `sortie`, and its GUI coupling is a single
  attribute (`_cardinal_frame`). The suite did not catch the deliver
  regression and structurally could not have.
- **`gui_shell_smoke.py`** (new; run directly, NOT named `test_*.py` — pytest
  collecting it aborts the entire run with INTERNALERROR because it needs a
  display and calls `sys.exit()`). It instantiates the real app and asserts:
  all six pages build and show exclusively; 11 tracked panels resolve to their
  expected page; all four `before=` reveal chains fire without `TclError`;
  `_on_reset` hides results, actions, AND the deliver button. **PASS.**
- **Screenshots** captured for all six steps against a live CRM fetch
  (11 open missions returned from Supabase).

## Known Limitations

- **No photo job has been run through the restyled GUI.** The shell is verified;
  the app as a job runner is not. This is the same Phase 3 GUI E2E gate that the
  OpenSplat work still owes.
- No visual regression baseline exists, so future restyles have nothing to diff.
- The smoke script asserts structure and reveal mechanics, not appearance. It
  cannot catch overlap, clipping, contrast, or truncation.
- Not tested at a second DPI scale or on a non-Windows Tk build.

## Out of Scope

`sortie_settings.json`, `rtklib/`, `.claude/` (pre-existing local state), and
anything not touched by `c401a83..HEAD`. No job logic, CRM contract, preset
mapping, or processing path was intentionally modified — flag it loudly if you
find one that was.
